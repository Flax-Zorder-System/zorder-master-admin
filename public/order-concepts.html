주문 개념 가이드

비개발자도 이해할 수 있는 핵심 개념 설명 · 실제 식당 시나리오 기반

💡 각 개념이 실제 식당에서 어떤 역할을 하는지를 중심으로 설명합니다. 결제 문제나 데이터 이상이 발생했을 때 어느 레이어를 확인해야 하는지 빠르게 파악할 수 있습니다.

개념 개요

ORDER SESSION오더 세션

손님이 자리에 앉는 순간부터 식사가 완전히 끝날 때까지의 전체 맥락을 담는 그릇입니다. "오늘 3번 테이블에서 어떤 일이 있었나?"를 파악할 수 있는 기록입니다.

착석 ~ 퇴석배달 / 테이크아웃 / 매장인원수테이블 정보Order와 1:1 연결KIOSK 모드 여부
ORDER오더

해당 세션에서 발생한 전체 주문의 금액 정보를 관리합니다. "이 테이블에서 총 얼마가 나왔나?"를 답하는 단위입니다.

총 금액세금 합계할인 / 크레딧OrderSession과 1:1
ORDER TICKET오더 티켓

손님이 한 번에 주문한 묶음입니다. 주문 버튼을 누를 때마다 티켓이 하나씩 생깁니다. 주방 디스플레이(KDS)나 주문서에 출력되는 단위입니다.

KDS 출력 단위주방 주문서주문 시각Order 내 여러 개 가능
CHECK체크

실제로 청구되는 단위입니다. 아이템별 가격·세금·수수료·차지가 확정되는 곳이며, 모든 주문에는 반드시 하나 이상의 Check가 존재합니다. 분할 결제 시 Check가 여러 개 생길 수 있습니다.

청구 단위가격 / 세금서비스차지 / 그래튜이티서비스피Order당 1개 이상 필수분할 결제 가능
PAYMENT페이먼트

Check에 대한 실제 결제 시도 단위입니다. 하나의 Check에 여러 번 결제가 일어날 수 있습니다. 예를 들어 카드 부분결제 후 현금으로 나머지를 내는 경우, Check 1개에 Payment가 2개 생깁니다.

결제 시도 단위Check와 N:1카드 / 현금 / 기타 수단부분결제 가능Transaction과 1:1
PAYMENT INTENT페이먼트 인텐트

손님이 태블릿에서 결제 버튼을 누른 순간 생성되는 결제 시도 기록입니다. 실제 카드 승인(Payment)이 완료되기 전까지의 과정을 추적합니다. 결제 실패나 이중 청구 문제 발생 시 원인 추적에 활용합니다.

결제 버튼 누름 시 생성만료 시간 존재실패 reason / detail 포함PENDING → SUCCESS / FAILED / EXPIRED
TRANSACTION트랜잭션

카드 네트워크와 실제로 통신한 기록입니다. Payment 1개당 Transaction 1개가 생성됩니다. Sale(승인), Void(취소), Refund(환불) 등 카드사와 주고받은 모든 통신 행위가 여기에 해당합니다. 현금 결제는 Transaction이 없습니다.

카드 네트워크 통신 단위Payment와 1:1Sale (승인)Void (취소)Refund (환불)Auth / Capture

상태값 참조

Order Session Status

OPEN 세션이 생성되었으나 아직 주문이 없는 초기 상태입니다.
SEATED 착석이 확인된 상태. 태블릿에서 인원 수 선택 완료 후 진입합니다.
ORDERED 최초 Order Ticket이 접수된 상태. 주방에 주문이 전달되었습니다.
CONFIRMED_ALL 모든 Order Ticket이 주방에서 확인(confirm)된 상태입니다.
CHECK_REQUESTED 손님이 태블릿에서 결제 요청을 누른 상태. 아직 결제 완료 전입니다.
POS_INTEGRATION_FAILED POS 연동 처리 중 오류가 발생한 상태. 운영팀 확인이 필요합니다.
CLOSED 모든 결제가 완료되어 세션이 정상 종료된 상태입니다.
CANCELLED 세션이 취소된 상태. 주문 없이 이탈하거나 관리자가 취소한 경우입니다.

Check Status

OPEN 아직 결제가 완료되지 않은 열린 Check입니다. 결제 진행 중이거나 대기 중입니다.
PAID 결제가 완료된 상태. 청구액 전액이 납부되었습니다.
CLOSED Check가 최종 닫힌 상태. PAID 후 세션 종료 시 전환됩니다.

Payment Intent Status

PENDING 결제가 진행 중입니다. 아직 완료되지 않았습니다.
SUCCESS 결제가 성공적으로 완료됐습니다.
FAILED 결제 시도가 실패했습니다. reason / detail 필드에서 원인을 확인할 수 있습니다.
EXPIRED 일정 시간 내 완료되지 않아 자동으로 만료됐습니다.

Check 구성 요소

Check는 아이템에 설정된 값에 따라 아래 요소들이 자동으로 계산됩니다.

💰 가격 (Price)
아이템 단가 × 수량
🧮 세금 (Tax)
아이템별 tax rate 또는 fixed amount 적용
➕ 서비스차지 (Service Charge)
자동 부과 서비스 수수료. Gratuity 포함 가능
📌 서비스피 (Service Fee)
배달비, 플랫폼 수수료 등 별도 청구 항목
🏷️ 할인 (Discount)
쿠폰, 멤버십, 프로모션 적용
💳 최종 청구액 (Total)
가격 + 세금 + 서비스차지 + 서비스피 − 할인
⚠️ 모든 Order에는 반드시 Check가 1개 이상 존재해야 합니다. Check 없이는 결제가 불가능합니다.
